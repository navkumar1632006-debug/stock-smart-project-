# StockSmart AI — Codebase Migration Plan
**Prototype (Fintech/Stock Analysis) ➔ Production (Hyperlocal Retail Intelligence SaaS)**

This document details the step-by-step architectural transition and component-level repurposing plan to pivot the existing stock-market code to the official **StockSmart AI Hyperlocal Retail Platform**.

---

## 1. Current Codebase vs. Target Alignment

| Legacy Fintech Asset | Reusability / Fate | Target Retail Module |
| :--- | :--- | :--- |
| **`src/components/StockDashboard.tsx`** | **90% Reusable (Structure)** | **`RetailDashboard.tsx`**<br>Repurpose financial stat cards to retail KPIs (Total Sales, Expiry Warnings, Active SKUs, Revenue). Replace portfolio tracker with "Active Inventory / Expiry Batches Log". |
| **`src/components/StockChart.tsx`** | **85% Reusable (Charts)** | **`SalesForecastChart.tsx`**<br>Repurpose historical stock lines into historical daily retail sales curves. Overlay the "Demand Forecast" line (generated by ML/Gemini). |
| **`src/components/InvestmentMindmap.tsx`**| **0% Reusable (Remove)** | **Remove Completely**<br>Fintech investment mindmaps are out of scope. Replace with a beautiful **`HyperlocalMarketplace.tsx`** map or layout interface. |
| **`src/components/AIStockAssistant.tsx`** | **80% Reusable (Chat)** | **`AIRetailAssistant.tsx`**<br>Pivot from stock advice to retail ops (e.g., inventory lookup, checking near-expiry batches, restock optimization insights). |
| **`src/lib/mockStockData.ts`** | **Replace (0% Reusable)** | **`mockRetailData.ts`**<br>Replace stock history lists with real retail products (e.g., Milk, Bread, Apples, Rice) containing `stockLevel`, `expiryDate`, `batchNo`, `originalPrice`, and `discountPrice`. |
| **`src/types/stock.ts`** | **Replace (0% Reusable)** | **`retail.ts`**<br>Replace stock/portfolio types with `Product`, `InventoryBatch`, `SaleRecord`, and `StoreLocation` interfaces. |

## 2. Technical Migration Roadmap

### Phase 1: Data Model Realignment
1. **Define Types (`src/types/retail.ts`)**:
   Establish clean structures for:
   * `Product`: `id`, `name`, `category`, `sku`, `price`, `cost`, `stockLevel`, `reorderPoint`.
   * `InventoryBatch`: `id`, `productId`, `batchNumber`, `expiryDate`, `quantity`, `discountRate`.
   * `Sale`: `id`, `productId`, `quantity`, `totalPrice`, `saleDate`, `channel`.
2. **Seed Mock Data (`src/lib/mockRetailData.ts`)**:
   Create a standard set of retail products with realistic stock levels, purchase costs, sale prices, and impending expiry dates (e.g., milk expiring in 2 days, organic bread expiring in 4 days).

### Phase 2: Refactoring Core UI Elements
1. **The Retailer Dashboard (`src/components/RetailDashboard.tsx`)**:
   * **KPIs**: Convert Watchlist and Live Tickers into "Critical Expiry Sprints" and "Out of Stock Alerts".
   * **Active Actions**: Convert "Buy/Sell Stock Form" into "Log New Sale" or "Receive Inventory Shipment" forms.
   * **Interactive Log**: Transform the portfolio ledger into an active inventory batches ledger showing "Days to Expiry" and "Dynamic Pricing Suggestions".
2. **The Sales & Forecast Chart (`src/components/SalesForecastChart.tsx`)**:
   * Change Recharts visualizer to display:
     * **Solid Curve**: Past 7-30 days of actual product sales (units).
     * **Dotted Curve**: Upcoming 7-day predicted demand forecast generated by the AI engine.
3. **The AI Retail Assistant (`src/components/AIRetailAssistant.tsx`)**:
   * Adjust the system instructions passed to Gemini via `/api/chat`.
   * The assistant should now analyze stock levels, notify when flour is running low, recommend discount percentages on yogurt expiring tomorrow, and handle customer product queries.

### Phase 3: Backend REST Route Pivot (`server.ts`)
1. **API Endpoints**:
   * Change `/api/news` (sentiment ticker) to `/api/inventory/alerts` (notifying about near-expiry batches).
   * Refactor `/api/chat` prompt injector to inject the active retail inventory lists and store information into the Gemini prompt context rather than stock company news.
2. **Remove Unused Middleware**:
   * Safely deprecate legacy financial calculators.

---

## 3. Preserving & Transitioning Existing Files
To ensure zero compilation errors and continuous operation:
1. We will **rename files gradually** or create the new components side-by-side with the old ones.
2. We will change the entry-point imports in `src/App.tsx` to mount the new **Retail Intelligence Platform** cleanly.
